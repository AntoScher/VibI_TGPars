Создай комплексную систему для сбора и анализа сообщений Telegram.

### Общая концепция
Проект состоит из трёх независимых, но взаимосвязанных асинхронных компонентов, которые работают с общей базой данных SQLite:
1.  **Сборщик сообщений (`main.py`)**: Скрипт на Telethon для сбора исторических и новых сообщений.
2.  **Телеграм-бот (`bot.py`)**: Бот на `pyTelegramBotAPI` для взаимодействия с собранными данными.
3.  **Веб-интерфейс (`web_app.py`)**: Веб-приложение на FastAPI для визуализации данных.

---

### Компонент 1: Сборщик сообщений (`main.py`)
-   **Библиотека**: `Telethon`.
-   **Функциональность**:
    -   Подключается к Telegram-аккаунту, используя `TG_API_ID` и `TG_API_HASH`.
    -   При старте собирает исторические сообщения из чатов, указанных в `TARGET_CHAT_IDS` в `.env` файле.
    -   Количество собираемых сообщений настраивается через `HISTORY_FETCH_LIMIT`.
    -   Если `TARGET_CHAT_IDS` не указан, для примера собирает сообщения из первого диалога в списке.
    -   После сбора истории запускает обработчик `events.NewMessage` для прослушивания новых сообщений в реальном времени.
    -   Все собранные сообщения сохраняются в базу данных SQLite через `db.py`.
    -   Ведется подробное логирование всех действий.

---

### Компонент 2: Телеграм-бот (`bot.py`)
-   **Библиотека**: `pyTelegramBotAPI` (асинхронная версия).
-   **Функциональность**:
    -   Использует токен `BOT_TOKEN` из `.env`.
    -   Реализована система доступа: бот отвечает только пользователям, чьи ID перечислены в `ALLOWED_USER_IDS`.
    -   **Команды**:
        -   `/start`, `/help`: Показывает приветственное сообщение со списком команд.
        -   `/stats`: Запрашивает статистику из БД (`get_db_stats`) и отправляет пользователю.
        -   `/search <слово>`: Ищет сообщения в БД по ключевому слову (`search_messages`).
        -   `/summary <текст>`: Отправляет текст на суммаризацию в сервис Deepseek через модуль `deepseek.py`.
    -   На любое другое текстовое сообщение бот отвечает эхом.

---

### Компонент 3: Веб-интерфейс (`web_app.py`)
-   **Фреймворк**: `FastAPI`.
-   **Шаблонизатор**: `Jinja2`.
-   **Функциональность**:
    -   **Главная страница (`/`)**: Отображает дашборд со статистикой из БД (используя `dashboard.html`).
    -   **Страница сообщений (`/messages`)**: Отображает все сообщения из БД с пагинацией (постраничным выводом). Использует `messages.html`.
    -   Все страницы должны наследоваться от базового шаблона `base.html` для единого стиля.

---

### Вспомогательные модули

#### `db.py` — Работа с базой данных
-   **Библиотека**: `aiosqlite`.
-   **Таблица**: `messages` (id, chat_id, sender, text, date) с составным первичным ключом (id, chat_id) для предотвращения дублей.
-   **Функции**:
    -   `init_db()`: Создает таблицу, если она не существует.
    -   `save_message()`: Сохраняет одно сообщение, обрабатывая дубликаты.
    -   `get_db_stats()`: Возвращает статистику (общее кол-во сообщений, уникальных чатов, дата последнего сообщения).
    -   `search_messages()`: Ищет сообщения по `LIKE` запросу.
    -   `fetch_paginated_messages()`: Возвращает "страницу" сообщений для пагинации в веб-интерфейсе.

#### `config.py` — Конфигурация
-   Загружает переменные из `.env` файла с помощью `python-dotenv`.
-   Использует `dataclass` для структурированного хранения конфигурации.
-   Проверяет наличие и корректность всех обязательных переменных при запуске.
-   **Переменные**: `TG_API_ID`, `TG_API_HASH`, `BOT_TOKEN`, `ALLOWED_USER_IDS`, `DEEPSEEK_API_KEY`, `TARGET_CHAT_IDS`, `HISTORY_FETCH_LIMIT`.

#### `deepseek.py` — Клиент для AI
-   **Библиотека**: `aiohttp`.
-   Реализует асинхронную функцию `generate_summary(text)`, которая отправляет запрос к API Deepseek.
-   Обрабатывает ошибки сети и API, выбрасывая кастомное исключение `DeepseekError`.
